# 📅 iCalendar 重复日程校验台（Recur Inspector）

一款**完全本地运行**的 iCalendar（ICS）重复日程展开与校验工具。粘贴或导入包含
`DTSTART`、`RRULE`、`RDATE`、`EXDATE`、`RECURRENCE-ID`（含 `RANGE=THISANDFUTURE`
范围例外）的日历文本，在指定日期范围内展开全部实例，验证例外覆盖、取消、
跨夏令时（DST）本地时刻与 `LOCATION` 冲突，并可交互式停用例外、修改规则后实时重算，
最终导出规范化 ICS。

- **技术栈**：React 18 + TypeScript + Vite 5 + [ical.js](https://github.com/kewisch/ical.js) 2.x
- **隐私**：纯前端静态应用，ICS 内容不出本机，无任何后端请求。

## 功能

| 能力 | 说明 |
| --- | --- |
| 重复展开 | RRULE（FREQ/INTERVAL/COUNT/UNTIL/BYxxx）、RDATE（含 PERIOD）、EXDATE、单次事件 |
| 例外覆盖 | `RECURRENCE-ID` 子事件**替换**对应原实例；改时间/地点/时长均以例外为准 |
| 范围例外 | `RECURRENCE-ID;RANGE=THISANDFUTURE`：以原始 recurrence key 判定影响范围，该次及后续实例起点按声明时区**墙钟位移**，并延续例外的时长/标题/地点/状态；多个范围例外按原始 key 顺序生效、后者覆盖前者 |
| 取消隐藏 | `STATUS:CANCELLED` 的实例不进入生效列表，只在「已取消」审计页留痕 |
| 跨 DST | 在事件**声明的 TZID 墙钟空间**迭代，墙钟时刻恒定，UTC 随偏移自动平移并标注 DST |
| 缺失时区兜底 | ICS 未携带 VTIMEZONE 时，用浏览器 `Intl` 时区数据库自动合成（含 DST 切换点） |
| 地点冲突 | 按相同非空 `LOCATION` 检测半开区间重叠，相切不算冲突 |
| 空闲窗口 | 基于当前生效实例，按 LOCATION + IANA 时区 + 日期范围 + 每日工作时段计算可容纳指定分钟数的空档；跨日事件按真实本地日界裁剪（DST 日 23/25 小时），忙碌区间相交或首尾相接即合并 |
| 联动定位 | 点击实例/冲突/告警/空档，右侧原始 ICS 高亮所属主事件块、RECURRENCE-ID 块与原始行号 |
| 例外停用 | 勾选框即时停用任意一条例外（含 CANCELLED 与范围例外），原实例立即恢复并重算冲突 |
| 规则编辑 | 就地修改 RRULE 文本，合法即实时重算；非法时显示解析错误并回退到上一条有效规则 |
| 变更影响 | 以 **UID + 原始 recurrence key** 为实例身份，比对原始日历与编辑后的生效实例：新增 / 移除 / 开始·结束移动 / 标题·地点·状态变化逐项列出前后值；移动不会误报成一删一增。支持按变更类型筛选，点击差异项联动实例表与 ICS 源码定位，无改动时显示空状态 |
| 规范化导出 | 输出 CRLF、RFC 5545 折行、按 UID 排序、内聚所需 VTIMEZONE（含合成时区），保留生效的 RANGE=THISANDFUTURE 例外组件，可下载/复制 |

## 一条命令启动（Docker）

需要已安装 Docker 20.10+ 与 Docker Compose v2：

```bash
docker compose up -d --build
```

启动后访问：

> **http://localhost:8080**

打开右栏「**空闲窗口**」页签即可使用空档查找（无需任何额外服务，纯前端静态托管）。

停止：

```bash
docker compose down
```

修改宿主机端口（如 9090）：编辑 `docker-compose.yml` 中 `"9090:80"` 后重新 `up -d`。

### 开发模式（Vite 热更新）

```bash
docker compose -f docker-compose.dev.yml up
```

访问 **http://localhost:5173**，修改 `src/` 即时热更新。

## 本地开发（无 Docker）

要求 Node.js 18+（推荐 20）：

```bash
npm install
npm run dev        # http://localhost:5173
```

其他命令：

```bash
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 本地预览生产构建 http://localhost:4173
npm run smoke      # 引擎语义冒烟测试（RRULE/RDATE/EXDATE/覆盖/范围例外/取消/DST/冲突/空闲窗口/导出）
```

## 使用指引

1. 左侧粘贴 ICS，或点「导入 .ics」选择文件；首次打开自带覆盖各类语义的示例。
2. 顶部「解析并展开」，在范围条设置起止日期（半开区间，按浏览器本地时区的日界）。
3. 三栏布局：
   - **左栏**：ICS 输入、解析告警、**原文行高亮**（蓝色=主事件块，紫色=例外块，
     红框=冲突方事件块，高亮行=RRULE/RDATE/EXDATE/RECURRENCE-ID 原始行）。
   - **中栏**：每个 UID 一张规则卡，可编辑 RRULE、勾选停用具条例外（含范围例外，
     卡片上标注「范围」与新起点），并显示 RDATE/EXDATE 清单与行号。
   - **右栏**：实例表五个页签——生效 / 已取消 / 已排除 / **空闲窗口** / **变更影响**；生效表支持地点关键字过滤与
     「仅看冲突」。「变更影响」比较原始日历与当前编辑（RRULE 修改、例外停用）后的差异，可按
     新增 / 移除 / 移动 / 字段变化筛选，重解析或调整日期范围后立即重算。DST 标记表示该实例相对
     序列首个实例的 UTC 偏移已变化。
4. 点击任一实例或差异项：右表选中、左栏原文同步定位；有冲突时冲突方事件块同步红框高亮。
   被移除的实例在生效表中以「已移除」幽灵行展示，仍可定位其原始块与行号。
5. **空闲窗口**：在页签内选择 `LOCATION`（下拉取生效实例中的非空地点）、IANA 时区（支持手输，
   如 `America/New_York`，默认浏览器时区）、日期范围、每日工作时段（墙钟 HH:MM，暂不支持跨午夜）
   与空档最小分钟数。列表按日期、开始时间排序，显示所选时区墙钟、UTC 偏移；跨 DST 的日期标注
   `DST 23h/25h`。点击任一空档：自动切回「生效实例」并高亮、滚动定位其**前 / 后相邻事件**
   （青色=前邻、紫色=后邻），顶部横幅可再次跳转或清除标记；行内相邻事件链接也可直接点击定位。
   规则编辑、例外停用或展开范围变化后空档立即重算（查询条件保留）。
6. 点右上「导出规范化 ICS」下载 `normalized.ics`，或「复制 ICS」到剪贴板。

## 语义约定

- **变更影响身份**：实例身份为 `UID#原始 recurrence key`（覆盖实例取 RECURRENCE-ID 对应时刻，
  普通 RRULE/RDATE/单次实例取原始起点；范围例外调整的实例同样保持原始 key）。
  覆盖改期与范围位移后两侧身份仍相同，只标记开始/结束移动；
  仅候选侧存在标为新增，仅原始侧存在标为移除。比对只纳入当前查询范围内的生效实例，
  已取消 / 已排除的审计行不参与。
- **范围例外（THISANDFUTURE）**：
  - 影响范围按**原始 recurrence key** 判定：原始 key ≥ 例外锚点（RECURRENCE-ID 对应时刻）
    的全部实例（含 RDATE 实例）都被调整，与实例当前是否已被位移无关。
  - 起点调整在**事件声明时区的墙钟空间**进行：位移量 = 例外 `DTSTART` 墙钟 −
    `RECURRENCE-ID` 墙钟；每个受影响实例的新起点 = 其原始墙钟 + 该位移，再按声明时区
    折算回绝对时间（跨 DST 时墙钟位移恒定，UTC 偏移随新墙钟日期自动变化）。
  - 受影响实例的**时长、标题、地点、状态**随范围例外延续（例外未声明的字段沿用主事件）。
  - 多个范围例外按原始 key 升序生效，**后者覆盖前者**：每个例外的位移都相对原始序列
    计算，不累积；`STATUS:CANCELLED` 的范围例外会取消该次及后续全部实例。
  - `EXDATE` 仍按**原始 key** 排除（被排除审计行显示范围调整后的时间）；
    **显式单次例外优先**于范围调整（同一 key 上单次例外完全接管该实例，
    范围位移继续作用于后续实例）。
  - 停用范围例外后，受影响实例立即回到前一范围例外（或基础序列）的状态并重算。
- **时间匹配**：EXDATE/RECURRENCE-ID 按绝对时刻匹配（DATE 型按当天 00:00）。
  请保证它们与 DTSTART 的时区形式一致（同为 `TZID=` 或同为 UTC `Z`）。
- **RDATE-PERIOD**：使用 PERIOD 自带的结束时间反推该实例时长。
- **无 DTEND/DURATION**：非全天事件时长按 0 处理，全天事件按 1 天处理（并告警提示）。
- **冲突**：只比较当前生效实例；全天事件参与检测；无 LOCATION 的事件不参与。
- **空闲窗口**：
  - 忙碌集仅包含当前**生效实例**（已取消 / 已排除 / 幽灵行不参与）且 `LOCATION` trim 后与所选值精确相等。
  - `VALUE=DATE` 全天事件的 `DTSTART`/`DTEND` 是**无时区公历日期**（并非 UTC 时刻）：查询任意
    IANA 时区时，一律按所选时区对应日期的**本地日界**重建半开区间——单日为
    `[当日00:00, 次日00:00)`，多日为 `[DTSTART 当地零点, DTEND 当地零点)`（`DTEND` 排他），
    绝不沿用 ical.js 登记的 UTC 午夜；因此 UTC+13 下的单日全天事件会整日覆盖 09:00–18:00。
  - 跨日事件先按**所选 IANA 时区**裁剪到每个本地日 `[00:00, 次日00:00)`，再与当日工作时段求交；
    本地日界用真实偏移换算，跨 DST 日为 23/25 小时，绝不固定按 86400 秒（全天重建的多日区间
    天然覆盖跳表/回秋日）。
  - 忙碌区间为半开区间，**相交或首尾相接**（下一个起点 ≤ 上一个终点）即合并，因此相切事件之间
    不会出现 0 分钟空档；空档 = 工作时段 − 合并后忙碌区间，长度 ≥ 最小分钟数才列出。
  - 相邻事件按“裁剪到当日的区间”判定：前邻为当日终点 ≤ 空档起点中结束最晚者，后邻为当日起点
    ≥ 空档终点中开始最早者；工作时段起点之前结束（不相接）的事件不计为前邻。
  - 每日工作时段为同一本地日内的墙钟区间，暂不支持跨午夜；日期范围上限一年。
- **合成 VTIMEZONE**：基于展开时间窗（DTSTART/UNTIL 年份前后取余量）探测 DST 切换点，
  仅保证窗内精确；导出的 ICS 建议在目标日历客户端复验。
- `RANGE=THISANDPRIOR` 已废弃且不在支持范围内（按单实例覆盖处理并给出告警）。

## 目录结构

```
src/
├── ical-engine/
│   ├── parser.ts       # 折行还原、行号索引、两遍解析（先注册时区再取值）、主子归组
│   ├── timezones.ts    # Intl 探测 DST 切换点，合成 VTIMEZONE
│   ├── expansion.ts    # RRULE 迭代 + RDATE/EXDATE/覆盖/取消 + THISANDFUTURE 范围例外 + 范围与上限
│   ├── conflicts.ts    # LOCATION 维度半开区间重叠检测
│   ├── free-windows.ts # 空闲窗口：跨日裁剪（真实 DST 日界）+ 忙碌区间合并 + 相邻事件
│   ├── diff.ts         # 变更影响：UID+原始 recurrence key 身份比对（新增/移除/移动/字段）
│   ├── normalizer.ts   # 规范化 ICS 输出（排序、时区内聚、规则/停用生效）
│   ├── types.ts        # 领域模型
│   └── samples.ts      # 内置示例
├── components/         # SourceView / InstanceTable / SeriesPanel / ChangeImpact / FreeWindows
├── utils/
│   ├── format.ts       # 墙钟/时长格式化与日期工具
│   └── localtime.ts    # IANA 时区墙钟⇄UTC、真实本地日界（DST 23/25h）
├── App.tsx
└── main.tsx
scripts/smoke.ts        # 引擎端到端冒烟测试
```
